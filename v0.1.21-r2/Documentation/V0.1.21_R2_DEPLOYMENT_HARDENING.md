# Auto Tracker v0.1.21-r2 Deployment Hardening

## Why r2 was created

r2 was created after a Windows deployment showed raw embedded JavaScript being interpreted by `cmd.exe`, producing repeated messages such as:

```text
'const' is not recognized as an internal or external command,
operable program or batch file.
```

The Windows launcher is a hybrid BAT + embedded JavaScript file. The BAT section must always stop before the exact `___JS_START___` payload marker. r2 repairs the launcher control flow and adds automated checks that reject missing/duplicate labels, embedded-source drift, and BAT fallthrough.

## Windows deployment fixes

- Added a real `:MENU_EXIT` target.
- Added the missing exact `:WAIT_FOR_NODE_READY` subroutine.
- Removed the duplicate `:MANUAL_NODE_INSTALL` label.
- Added a hard `goto :EOF` before the embedded JavaScript payload.
- Declares the startup error log before controller preparation.
- Verifies every BAT `call :label` and `goto label` has exactly one target.
- Keeps exactly one real `___JS_START___` marker line and one quoted extraction reference.
- Ensures the embedded controller is byte-equivalent to the canonical Node controller.
- Adds port-9000 detection before startup and will not automatically terminate a non-Node listener.
- Supports a same-folder `TamperMonkey Mods` file.
- Supports a same-folder `server.js` file.
- Preserves a same/newer installed controller instead of replacing it with an older packaged source.
- Synchronizes and validates the runtime Tampermonkey userscript before startup.

## Agent runtime location on Windows

The launcher resolves Windows' actual Desktop path instead of assuming `C:\Users\<name>\Desktop`.

Runtime files are stored under:

```text
Desktop\JobTrackerServer\
├─ server.js
├─ package.json
├─ package-lock.json              (when supplied)
├─ node_modules\
├─ Tampermonkey_Modifications\
│  └─ TamperMonkey Mods
├─ Logs\
├─ Reports\
├─ Backups\
├─ Integrity_Quarantine\         (when required)
├─ report-upload-config.json
├─ stats.json
└─ tracker state/integrity files
```

The approved simple Windows agent package can be:

```text
Auto_Tracker.bat
TamperMonkey Mods
```

The BAT contains the compatible embedded controller and creates the required runtime folders/files. The complete repository-style package remains supported for IT testing.

## Controller/API hardening

- Controller now listens on `127.0.0.1:9000` instead of all network interfaces.
- Wildcard CORS was removed.
- Requests with an unapproved web origin are rejected.
- Local POST request bodies have a size limit.
- Dashboard static-file requests are confined to the dashboard folder.
- JavaScript dashboard files use the correct JavaScript MIME type.
- Port/listen errors are written as clear startup diagnostics.
- Reset All requires a controller-side confirmation flag, not only a browser confirmation.
- Confirmation/Coverage mode cannot be changed while Break, Lunch, BIO, or HBIO is active.
- Active-shift identity locking includes Agent ID, Agent Name, Last Name, Department, and Pod.

## Report and Apps Script integrity fixes

- Upload authentication binds Agent Name in addition to Agent ID, Last Name, Department, and Pod.
- Legacy two-part CWH/DailyAgentReports keys correctly migrate into OOS instead of creating a duplicate row.
- Department-scoped r2 filenames such as `Ballados_2026-10-03_OOS.xlsx` and `..._ENCORD.xlsx` are recognized by 7-day Drive retention.
- Dynamic validated Pod names are used consistently in retention and migration.
- PodDirectory OOS/ENCORD sorting no longer treats OOS order `0` as a missing value.
- Device revoke refreshes PodDirectory immediately.
- `addPod()` returns the actual Pod folder ID and reports the Department folder separately.
- Drive XLSX replacement is serialized and creates/checks the new file before trashing the previous good copy.
- Team Lead updates preserve an existing credential instead of rotating it unexpectedly.
- New Team Lead credentials are no longer written into Apps Script execution logs.
- Team Lead Overall now includes OT BIO and OT HBIO totals.
- Apps Script and Team Lead Controller user-facing version labels are aligned to v0.1.21-r2.

## Tampermonkey Break/Resume recovery

- Resume now clears a stale Break/Lunch `activeKind` when the controller explicitly returns `activeKind: null`.
- The `tracker-break-focus` view is removed immediately after a successful Resume.
- The normal dashboard becomes visible again without requiring a page refresh.
- A regression test reproduces Break -> Resume -> main dashboard recovery.

## ENCORD/OOS display and logging fixes

- ENCORD console display shows independent 30-minute Break and 60-minute Lunch allowances.
- OOS day and mid/night shift labels reflect their actual pause policies.
- Break/Lunch logs use the actual active pause type.
- End Shift TXT summary includes Break, Lunch, OT Break, OT Lunch, OT BIO, and OT HBIO.

## Linux/macOS deployment fixes

Linux:
- Supports same-folder `TamperMonkey Mods`.
- Compares controller version + revision before copying packaged code, so a same/newer Drive-updated runtime is preserved.
- Can recover the embedded controller from `Auto_Tracker.bat` without requiring Python.
- Verifies the service on `127.0.0.1:9000/stats` before treating a port listener as Auto Tracker.
- Reuses a same/newer running controller instead of starting a duplicate.
- Refuses to terminate an unrelated port-9000 process.
- Refuses to replace an older tracker while an active shift is running.
- Uses the lockfile/cache-aware npm path when available and skips npm when ExcelJS is already ready.

macOS:
- Supports repository-style, compatibility-folder, or same-folder Tampermonkey source.
- Creates the backup before replacing the runtime controller.
- Compares controller version + revision before copying packaged code, preserving a same/newer Drive-updated runtime.
- Can recover the embedded controller from a compatible `Auto_Tracker.bat` fallback when present.
- Verifies and reuses a same/newer running controller on port 9000.
- Refuses to terminate unrelated port-9000 listeners or replace an older tracker during an active shift.
- Uses the same faster dependency-install path as Windows/Linux.
- Keeps Gatekeeper and certificate/security protections enabled.

## Automated validation

The r2 workflow validates:
- Node 20
- Node 24
- Node/Tampermonkey syntax
- Linux/macOS shell syntax
- Apps Script syntax and duplicate-function integrity
- release/update behavior
- installer safety
- Break/Lunch/Idle behavior
- interval/report calculations
- v20 migration behavior
- live local controller runtime smoke
- r2 deployment-hardening rules
- calculation regression
- an actual Windows BAT runtime smoke on `windows-latest`
- an actual Linux launcher runtime smoke on `ubuntu-latest`
- an actual macOS launcher runtime smoke on `macos-latest`

The Linux/macOS smoke jobs start the controller, verify v0.1.21-r2 at `127.0.0.1:9000/stats`, run the launcher a second time, confirm that the existing controller is reused, and verify that the first controller remains healthy.

Windows smoke specifically verifies that:
1. menu Exit completes without JavaScript fallthrough;
2. Start Tracker launches through `cmd.exe`;
3. the controller answers at `http://127.0.0.1:9000/stats`;
4. the running controller reports v0.1.21 revision 2.

## Still required before mass deployment

Repository CI cannot replace production canaries. Before publishing final release checksums:
- deploy the repaired Apps Script to a test/production Web App;
- perform one real report upload and verify Drive + DailyAgentReports;
- generate Team Lead Daily and Overall sheets for assigned Pods;
- test Windows 10 clean install and v0.1.20 upgrade on real agent PCs;
- test Linux Mint/Ubuntu;
- test macOS Intel and Apple Silicon;
- decide/finalize real Pod heartbeat status and the dedicated audited Pod-transfer workflow;
- verify the old v0.1.18/v0.1.19 one-time upgrade/bootstrap path.

Do not generate or publish the final r2 SHA-256 values until the exact release files have passed those canaries and will no longer be edited.
