# Auto Tracker v0.1.21-r2 Installation Package Guide

Use only files from the same approved r2 commit/release. Do not mix an older BAT, server.js, or TamperMonkey Mods file with a newer package.

## Windows

### Recommended fast first-time package

```text
Auto Tracker v0.1.21-r2/
├─ Auto_Tracker.bat
├─ TamperMonkey Mods
├─ package.json
└─ package-lock.json
```

The two-file package (`Auto_Tracker.bat` + `TamperMonkey Mods`) is still supported, but including `package.json` and `package-lock.json` lets first-time setup use deterministic `npm ci` and the npm cache.

Installed runtime location:

```text
Desktop/JobTrackerServer/
```

The Windows launcher creates the runtime folders, extracts/copies the controller, installs ExcelJS only when required, and reuses an already-running same/newer r2 controller.

## Linux

Recommended package:

```text
Auto Tracker v0.1.21-r2/
├─ Auto_Tracker.sh
├─ server.js
├─ TamperMonkey Mods
├─ package.json
└─ package-lock.json
```

Optional compatibility fallback:
```text
Auto_Tracker.bat
```

If `server.js` is missing/invalid and the compatible BAT is present, Linux can extract the embedded controller without Python.

One-time permission:

```bash
chmod +x Auto_Tracker.sh
```

Start:

```bash
./Auto_Tracker.sh
```

Do not run the tracker itself with `sudo`.

## macOS

Recommended package:

```text
Auto Tracker v0.1.21-r2/
├─ Auto_Tracker_macOS.command
├─ server.js
├─ TamperMonkey Mods
├─ package.json
└─ package-lock.json
```

Optional compatibility fallback:
```text
Auto_Tracker.bat
```

One-time permission if Finder/download extraction removed the executable bit:

```bash
chmod +x Auto_Tracker_macOS.command
./Auto_Tracker_macOS.command
```

Do not disable Gatekeeper. The installer does not require that.

## Shared Rev2 installation protections

All three platforms now follow these rules:

- The current controller is identified as v0.1.21 revision 2.
- A same/newer installed runtime is not replaced by an older packaged controller.
- A same/newer controller already running on `127.0.0.1:9000` is reused.
- An unrelated application on port 9000 is never terminated automatically.
- An older verified tracker is not replaced while it has an active shift.
- ExcelJS installation is skipped when already ready.
- With `package-lock.json`, first-time dependency installation prefers `npm ci --omit=optional --prefer-offline --no-audit --no-fund --progress=false`.
- Without a lockfile, setup installs exact `exceljs@4.4.0`.
- Setup/runtime errors are written under `Logs`.
- Existing tracker state is backed up before risky replacement work.
- Tampermonkey Break -> Resume clears the pause-focus screen and returns to the main dashboard.

## Canary checks before broad rollout

For each OS, test at least one real device:

1. First-time install.
2. Start controller and verify the tracker connects.
3. Complete First-Time / Device Setup.
4. Start Shift.
5. Start Break, then click Resume and verify the main dashboard returns immediately.
6. Start the launcher a second time and verify it reuses the existing controller.
7. Generate a report.
8. Verify report upload and DailyAgentReports.
9. End Shift normally.
10. Confirm Logs and Reports were created and no unexpected error was recorded.

Do not publish final release checksums until the exact files used for the canaries are frozen.
